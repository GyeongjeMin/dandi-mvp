# 단디(DANDI) — AI 기반 시니어 정서 돌봄 웹 MVP

> 어르신의 일상 대화에서 **생애기억**을 쌓고, 그 기억으로 **회상 대화**를 이어가며,
> 경험·취미가 비슷한 어르신을 **이어 주는** AI 말벗 서비스의 웹 시연 버전입니다.
> 최종적으로는 인형형 AI 돌봄로봇에 탑재할 소프트웨어의 핵심 기능을 웹에서 구현했습니다.

2026 모두의 창업 프로젝트 2라운드 진출평가 제출용 프로토타입입니다.

---

## 1. 핵심 기능 (세 기능이 하나의 데이터 흐름으로 연결됨)

| # | 기능 | 실제로 동작하는 것 |
|---|------|------------------|
| 1 | **생애기억을 쌓는 AI 대화** | 대화 → 직업·취미·지역·가족·생애경험 추출 → JSON 검증 → 중복 검사 → “기억해도 될까요?” 확인 → DB 저장 |
| 2 | **기억 기반 회상 대화** | 새 대화를 시작하면 저장된 기억으로 첫 질문을 건넴 / ‘나의 추억’에서 기억별 회상 질문 생성 → 그 질문으로 대화 시작 |
| 3 | **AI 기반 동네 친구 추천** | 확인된 기억의 태그 + 공개 동의한 지역으로 가중치 유사도 계산 → 공통점·추천 이유 자동 생성 → 대화로 관심사가 바뀌면 순위·이유도 바뀜 |
| + | **교류 연결** | 제안 → 상대방 수락/거절(시연용 버튼으로만 변경, 자동 수락 없음) → 양측 동의 시 연결 완료 |

```
[대화]──추출(AI/규칙)──▶[확인 대기 기억]──이용자 확인──▶[확정 기억]──태그──▶[interests]──가중치 유사도──▶[추천]──▶[교류 제안]
                                                              │
                                                              └──관련 기억 검색──▶[다음 대화·회상 질문]
```

## 2. 화면 구성

이용자를 **어르신**과 **가족·보호자** 두 유형으로 나눴습니다. 두 화면은 따로 쓰지만 같은 어르신 계정·기억 데이터에 연결됩니다.

### 어르신용 (메뉴 4개: 단디 · 나의 추억 · 가족 소식 · 더보기)

| 화면 | 주소 | 내용 |
|------|------|------|
| 시작하기 | (첫 방문) | 서비스 소개, 별명·연령대·지역, 지역 공개 범위, **기억 저장 동의 / 친구 추천 동의(각각 따로)** |
| **처음 화면** | `#/` | 단디 캐릭터를 크게, **[단디와 이야기하기] 버튼 하나**, 지금 챙길 복약·생활 알림, 나의 추억·가족 소식 바로가기 |
| **음성 대화** | (처음 화면에서 버튼) | **가운데에 3D 단디**(실제 대화 이벤트로 듣기·생각·말하기·기쁨·공감 연기, 끌어서 돌리기), 듣는 중 / 생각하는 중 / 말하는 중 상태 문구, 큰 자막, 말 끊기, 대화 끝내기, “응/아니”로 기억 저장·가족 소식 보기, 마이크·네트워크 오류 안내, 글자로 말하기 |

| **가족 소식** | `#/news` | 가족이 보낸 사진·메시지, [이 소식으로 단디와 이야기하기] |
| 더보기 | `#/more` | 아래 세부 기능 모음 |
| └ 글자로 이야기하기 | `#/chat` | 기존 채팅 화면 (지난 대화 보기 포함) |
| └ 이야기 한눈에 보기 | `#/overview` | 기존 홈 (최근 추억·대화·오늘의 이야깃거리) |
| └ **가족 연결과 알림** | `#/care` | 가족 초대 숫자(6자리·24시간), 공유 범위(이용 현황 / 대화 주제), 연결된 가족·연결 끊기, 복약·생활 알림 |

모든 하위 화면 위에 **[← 뒤로] [처음 화면]** 버튼이 있어 잘못 눌러도 바로 돌아갈 수 있습니다.

## 3. 사용 기술

- 프론트엔드: React 19 + Vite 7 + TypeScript + Tailwind CSS 4 (라우터는 해시 방식으로 직접 구현, 추가 의존성 없음)
- 3D: Three.js 0.170 (GLB 모델 `client/public/models/dandi.glb`, 생성 스크립트 `client/scripts/build-dandi-model.mjs` → `npm run model --prefix client`)
- 백엔드: Node.js + Express 5 + TypeScript(tsx로 바로 실행)
- 데이터베이스: SQLite — **Node 내장 `node:sqlite`** 사용 (Windows에서 C++ 빌드 도구 없이 설치되도록 네이티브 모듈을 쓰지 않음)
- AI: 교체 가능한 LLM 어댑터 — Anthropic Claude, OpenAI 및 OpenAI 호환 API(Ollama 등), API 키가 없으면 규칙 기반 데모 엔진

## 4. 설치 및 실행 (Windows 기준)

### 준비물
1. **Node.js 24 LTS** (최소 22.13 이상) — https://nodejs.org 에서 LTS 설치
2. VS Code (선택)

### 가장 쉬운 방법
압축을 푼 폴더에서 **`start-windows.bat` 을 더블클릭**하세요. 처음에는 패키지를 설치(인터넷 필요, 몇 분)하고, 이후 브라우저가 `http://localhost:5173` 으로 열립니다.

### VS Code 터미널에서
```powershell
cd dandi                        # 압축을 푼 폴더
npm run setup                   # server, client 패키지 설치 (처음 한 번)
copy server\.env.example server\.env   # 환경변수 파일 만들기 (안 해도 데모 모드로 실행됨)
npm run dev                     # 백엔드(4000) + 프론트엔드(5173) 동시 실행
```
브라우저에서 **http://localhost:5173** 을 엽니다. 종료는 터미널에서 `Ctrl + C`.

### 그 밖의 명령
| 명령 | 설명 |
|------|------|
| `npm test` | 시나리오 A~F + 개인정보 + AI 연동 경로 자동 테스트 (실제 DB는 건드리지 않음) |
| `npm run db:reset` | DB 초기화 (서버를 끈 상태에서). 시연 전에 깨끗한 상태로 만들 때 사용 |
| `npm run build` 후 `npm start` | 프론트를 빌드해 백엔드 하나(`http://localhost:4000`)로 실행 |

### 문제가 생겼을 때
- **`start-windows.bat` 실행 시 이상한 글자와 함께 "내부 또는 외부 명령…이 아닙니다"** → 예전 버전의 배치 파일입니다. 최신 압축 파일의 `start-windows.bat`(영문 메시지)을 쓰시거나, 아래 터미널 방법으로 실행하세요.
- **"server 폴더에 패키지가 설치되지 않았어요"** → `npm run setup` 을 먼저 실행하세요(인터넷 필요).
- **`npm` 명령을 찾을 수 없음** → Node.js 설치 후 VS Code/터미널을 완전히 껐다가 다시 여세요.
- **PowerShell에서 "스크립트를 실행할 수 없으므로…" 오류** → VS Code 터미널 종류를 *Command Prompt* 로 바꾸거나, PowerShell에서 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 를 한 번 실행하세요.
- **포트 사용 중(EADDRINUSE)** → 이전에 켠 단디 창을 닫거나 컴퓨터를 재시작하세요.

> Node 22에서는 실행할 때 `ExperimentalWarning: SQLite ...` 경고가 보일 수 있습니다. 정상이며 동작에는 영향이 없습니다.

## 5. 환경변수 (`server/.env`)

| 이름 | 기본값 | 설명 |
|------|-------|------|
| `LLM_PROVIDER` | `demo` | `demo` / `anthropic` / `openai` |
| `ANTHROPIC_API_KEY` | – | Anthropic API 키 |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | 더 빠르고 저렴하게: `claude-haiku-5-5` |
| `OPENAI_API_KEY` | – | OpenAI(또는 호환 서버) 키 |
| `OPENAI_MODEL` | – | 사용할 모델 이름 (반드시 입력) |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Ollama 등 호환 서버 주소로 바꿀 수 있음 |
| `PORT` | `4000` | 백엔드 포트 |
| `DB_FILE` | `./data/dandi.sqlite` | DB 파일 위치 |

- API 키는 **백엔드에서만** 읽고, 브라우저로 보내는 어떤 응답에도 포함하지 않습니다(자동 테스트 AI-2에서 확인).
- 키가 비어 있거나 설정이 잘못되면 자동으로 데모 모드로 실행하고, 화면의 ‘데모 모드’ 배지를 누르면 이유가 표시됩니다.
- AI 호출이 실패하면 그 답만 규칙 기반 문장으로 대신하고 말풍선에 ‘대체 응답’으로 표시합니다.

## 6. 시연 순서 (약 7분, 시나리오 A~F)

시작 전: `npm run db:reset` → `npm run dev` → 브라우저 `http://localhost:5173` (예전에 쓰던 브라우저라면 ‘내 정보 → 모든 정보 지우기’ 또는 시크릿 창 사용)

1. **시작하기** → `🎬 시연용 예시로 채우기` → 두 가지 동의가 **따로** 있음을 보여 주고 ‘단디 만나러 가기’
2. **[A] 기억 저장** — 이야기 화면에서 예시 칩 “젊었을 때 진주에서 작은 식당을 운영했었지.” 전송 → 단디가 공감·질문 → “기억해도 될까요?” 카드에서 **기억할게요** → ‘나의 추억’에서 카드·추출 시각·출처 대화 확인
3. **[B] 회상 대화** — 이야기 화면에서 **＋ 새 이야기** → 단디가 저장된 식당 기억으로 먼저 질문(‘단디가 떠올린 추억: 식당 운영’ 표시). ‘나의 추억’에서 **회상 질문 만들기** → **이 질문으로 이야기 나누기**
4. **동네 친구** 한 번 열어 현재 순위 확인 (정순·영호·덕수…)
5. **[C] 네트워킹** — “요즘은 텃밭 가꾸기를 좋아해.” → 기억할게요 → **동네 친구**: “새로 반영: 텃밭 가꾸기” 알림, 덕수님 ‘▲ 3위에서 올라옴’, 추천 이유에 텃밭이 들어감, ‘점수 자세히 보기’로 항목별 점수
6. **[D] 교류 연결** — 덕수님께 교류 제안 → 시연 모드 안내 확인 → 교류 화면에서 **‘덕수님으로 수락’**(또는 다른 분께 제안 후 ‘거절’) → 단계 표시와 ‘연결 완료’, 연락처 비공개 안내
7. **[E] 기억 관리** — ‘나의 추억’ → 텃밭 카드 **고치기** → 제목 “등산”, 내용 “주말마다 등산을 다녀” 저장 → 동네 친구: 영호·재석님이 위로, 텃밭 공통점 사라짐. 카드 **지우기**로 삭제도 시연
8. **[F] 데이터 지속성** — 브라우저 새로고침(F5) 또는 서버 재시작 후에도 추억·추천 유지, 새 대화에서도 회상
9. (보너스) “손주들이 너무 보고 싶어.” → ‘가족’ 기억 + **🤔 단디의 짐작** 후보가 따로 표시됨, 가족 기억은 친구 추천에 쓰이지 않음

> 2차 개선 후에는 위의 ‘이야기 화면’이 **더보기 → 글자로 이야기하기**(`#/chat`)에 있습니다.

### 2차 개선 시연 (음성 대화 · 가족 연계, 약 5분)

준비: Chrome 또는 Edge, 마이크, `http://localhost:5173` (localhost 주소여야 마이크 사용 가능). 가족 화면은 **다른 브라우저나 시크릿 창**에서 열면 두 사람이 쓰는 모습을 동시에 보여 줄 수 있습니다.

1. **어르신 처음 화면** — 단디와 큰 버튼 하나. **[단디와 이야기하기]** → 마이크 허용 → 단디가 먼저 인사
2. **음성 대화** — “젊었을 때 진주에서 작은 식당을 운영했었지.” → 상태가 *듣고 있어요 → 생각하고 있어요 → 말하고 있어요*로 바뀌고, 단디가 “‘식당 운영’ 이야기, 단디가 기억해 둬도 될까요?” → “응” → 저장 후 아까 질문을 이어감. 단디가 말할 때 **[말 끊고 제가 말할게요]**, 마지막에 “오늘은 여기까지 할게” 또는 **[대화 끝내기]**
3. **공유 설정** — 더보기 → 가족 연결과 알림 → 이용 현황·대화 주제 공유 켜기 → **초대 숫자 만들기** / 나의 추억 → 식당 카드 **[가족과 공유]**
4. **가족 화면** (`#/family`) — 숫자·이름·관계로 연결 → 돌봄 현황(실제 기록, 대화 내용은 안 보임) → **소식 보내기**에 사진·메시지 → **공유된 추억**에 질문 “그 식당 이름이 뭐였어요?” → **알림 관리**에 지금 시각으로 ‘혈압약’
5. **어르신 화면** — 처음 화면에 *새 소식 1개*·*지금 챙길 알림*. [단디와 이야기하기] → 단디가 “딸 ○○ 님이 사진을 보내왔어요. 지금 같이 보실까요?” → “응” → 사진이 크게 뜨고 이야기 이어감. 다음 대화에서는 가족의 질문을 대신 여쭤봄
6. **가족 화면 새로고침** — 소식 상태 ‘단디와 함께 이야기함’, 질문 ‘단디가 여쭤봤어요’, 알림 ‘오늘 확인함’(어르신이 [했어요] 또는 “약 먹었어”)

## 8. 데이터 저장 및 추천 구조

### 테이블

| `interests` | **확정된** 기억에서 파생된 추천용 태그(직업·취미·관심사·경험). 기억 수정·삭제 시 자동 재계산. 가족 기억은 제외 |
| `recommendations` | 추천 결과 스냅샷(최근 2회) — 순위 변화와 “새로 반영된 관심사” 표시에 사용 |
| `connection_requests` | 교류 제안, 상태(pending/accepted/declined/cancelled), 시연 여부 |

### 기억 처리 원칙
- 추출 결과는 `{"memories":[{category,title,detail,tags,certainty}]}` JSON으로 받고 **항목별로 형식 검증**(잘못된 항목만 버림, 코드블록·앞뒤 설명 허용).
- 자유 형식 태그는 **표준 태그 사전**으로 정규화(예: “텃밭 농사” → `텃밭 가꾸기`).
- **중복 처리**: 같은 범주에서 핵심 표준 태그가 겹치거나 제목 유사도(문자 2-gram Dice) ≥ 0.7 이면 저장하지 않고 “이미 기억하고 있는 이야기”로 표시.
- 모든 추출 결과는 **확인 대기**로 저장 → 이용자가 확인해야 대화·추천에 사용. AI의 짐작(`inferred`)은 화면에 ‘단디의 짐작’으로 따로 표시.
- 응답 프롬프트에는 확인된 기억만 넣고, “목록에 없는 과거·가족·건강·사는 곳을 지어내지 말 것”을 명시.

### 추천 점수 (태그 기반 가중치 유사도)
```
항목 유사도 = (같은 태그 수 + 0.5 × 같은 계열 태그 쌍 수) ÷ min(내 태그 수, 상대 태그 수)
           (계열 예: 식당 운영·반찬가게·급식 조리 = '음식' 관련 일)
지역 유사도 = 같은 시·군·구 1.0 / 같은 시·도 0.5 (양쪽 공개 동의 범위 안에서만)
점수 = Σ(가중치 × 유사도) ÷ Σ(내 정보가 있는 항목의 가중치) × 100
가중치 = 취미 35% · 직업 경험 25% · 관심사 20% · 경험·지역 10% · 사는 지역 10%
```
- 대화로 알게 된 공통점이 하나도 없으면(지역만 같으면) 추천하지 않습니다.
- 추천 이유 문장은 실제로 겹친 태그·계열·지역으로만 조립합니다(미리 써 둔 문구 없음). 예:
  > 정순님은 봄날님처럼 텃밭 가꾸기에 관심이 많아요. 두 분 모두 과거 음식 관련 일을 하신 경험이 있어요(식당 운영 · 반찬가게). 정순님도 봄날님처럼 진주에서 지내셨고, 지금도 같은 진주시에 사셔서 가까이에서 만나기 좋아요. 공통된 이야기를 나누기 좋을 것 같아요.

## 9. 개인정보 및 안전 설계 (MVP 반영 사항)

- 기억 저장 동의와 친구 추천 동의를 **따로** 받고, 언제든 끌 수 있음 (끄면 새 기억 저장·추천 중단)
- “기억해도 될까요?” 확인을 거친 것만 저장, 모든 기억 조회·수정·삭제 가능, 출처 대화 표시
- **가족 기억은 추천 데이터로 쓰지 않음**(코드에서 강제), 기억별 ‘추천 제외’ 설정
- 다른 이용자에게는 별명·연령대·공개 범위 지역·태그만 보임 — 기억 원문, 연락처, 상세 주소는 저장·노출하지 않음
- 연결은 상대방 수락이 있어야만 완료, 시연용 응답은 사람이 버튼을 눌러야만 바뀜
- 이용자별 데이터 분리(모든 쿼리에 이용자 ID 조건), 가상 이용자 계정으로는 접근 불가
- API 키는 서버 환경변수에만 보관, `.env`는 `.gitignore` 처리, 내부 오류 내용은 화면에 노출하지 않음
- ‘모든 정보 지우기’로 이용자 관련 데이터 일괄 삭제(연쇄 삭제)

> ⚠️ **위 구현이 상용 서비스 수준의 법적·보안 요건을 모두 충족한다는 뜻은 아닙니다.**
> 이 MVP에는 로그인/본인인증이 없어 브라우저에 저장된 이용자 번호만으로 이용자를 구분하며, DB 암호화·접근 기록·보존 기간 정책도 없습니다.
> 실제 출시 전에는 개인정보 보호법(민감정보·제3자 제공 동의 등), 의료·돌봄 관련 규정, LLM 외부 전송에 대한 고지·동의, 보안 점검을 별도로 거쳐야 합니다.

| 3D 캐릭터 ↔ 음성 대화 연동 | Chrome 헤드리스(소프트웨어 WebGL)에서 음성 대화 진행 후 상태 기록 확인 | 인사(말하기·기쁨) → 듣기 → 생각(중립) → 표정 도착 → 말하기·기쁨 → 듣기 → 생각 → 말하기·공감 → 듣기 순서로 전환 확인, 상태별 렌더 이미지 확인 |

**확인하지 못한 것 (꼭 직접 확인해 주세요)**
- **실제 마이크로 말하는 음성 인식**은 자동 테스트로 확인할 수 없었습니다(가짜 마이크는 말소리를 내지 않음). 크롬·엣지·사파리에서 직접 말해 보며 인식률과 끊김을 확인해 주세요.
- 실제 Anthropic/OpenAI API 호출(스트리밍 포함)은 하지 못했습니다. 요청·응답 처리 경로는 가짜 서버로 검증했습니다.
- 기존 DB 마이그레이션은 옛 구조 DB를 만들어 테스트했고, 개발 중인 실제 DB에도 적용되었습니다. 적용 전 백업: `server/data/backup/dandi-before-v2.sqlite`

## 11. 현재 구현 범위와 향후 과제

**구현됨 (실제 동작)**
- 대화·기억 추출·확인·저장, JSON 검증·중복 처리, 직접 말함/AI 짐작 구분, 관련 기억 검색, 회상 질문, 기억 관리, 가중치 추천·추천 이유, 교류 제안, 동의 관리, 데모/AI 모드 구분 (기존)
- **음성 대화**: 버튼 한 번으로 시작 → 자동으로 듣고 → 답을 스트리밍으로 받아 **첫 문장이 완성되는 즉시 읽기 시작** → 다 읽으면 다시 듣기. 말 끊기, “응/아니”로 기억 저장·가족 소식 보기, “오늘은 여기까지” 하면 마무리 인사, 대화 기록 저장(음성/글자 구분, 종료 시각)
- **장기기억 개선**: ‘최근 관심사 및 일상’ 범주, 어제·그저께 이야기의 후속 질문, 인사말·일상 질문 반복 방지, 하루 안에 꺼낸 기억은 다시 꺼내지 않기, 길게 대답하신 기억을 ‘좋아하는 주제’로 우선, 피하고 싶은 이야기 제외, AI에 최근 질문 목록을 주어 같은 질문 반복 금지
- **가족 연계**: 초대 숫자 연결, 공유 범위(어르신이 직접), 이용 현황(실제 기록만), 관심사 이름 요약, 사진·메시지 → 단디가 대화에서 소개, 공유 추억 댓글·질문 → 단디가 대신 여쭤봄, 복약·생활 알림(화면이 열려 있을 때), 연결 끊기, 전체 삭제 시 사진 파일까지 삭제
- **3D 단디 캐릭터**: 제품 사진 비율로 만든 GLB 모델 + 상태 머신 기반 절차적 애니메이션(대기·듣기·생각·말하기 + 기쁨·공감 표정), 음성 대화 이벤트와 실시간 연동, 움직임 줄이기 옵션 — 자세한 내용 [docs/3d-model.md](docs/3d-model.md)
- **대화 방식**(말 길이·목소리 빠르기·피할 이야기)과 공유 범위는 **기기가 아닌 계정에 저장** → 휴대폰·태블릿·향후 전용 기기에서 같은 계정·기억을 그대로 사용

**웹 브라우저의 제약 (작동하는 것처럼 표시하지 않음)**
- 음성 인식: Chrome·Edge(PC·안드로이드), Safari(iOS 14.5+)만 지원. Firefox 불가. Chrome 음성 인식은 인터넷 필요. 마이크는 **https 또는 localhost 주소에서만** 사용 가능(같은 와이파이의 휴대폰으로 `http://컴퓨터IP:5173` 접속 시 마이크 불가 → https 배포 필요)
- 단디가 말하는 동안에는 듣지 않습니다(스피커 소리를 어르신 말로 오인하는 것 방지). 대신 **[말 끊고 제가 말할게요]** 버튼으로 즉시 끼어들 수 있습니다. 말소리로 끼어들기(barge-in)는 브라우저 에코 제거가 기기마다 달라 이번 범위에서 제외
- 목소리는 기기에 설치된 한국어 음성을 사용합니다(자연스러움이 기기마다 다름). 서버형 음성합성(TTS)·음성인식(STT)은 미적용
- 알림은 앱 화면이 열려 있을 때만 안내합니다. **푸시 알림·문자·전화 없음**. 이용을 재촉하는 반복 알림은 의도적으로 만들지 않았습니다
- 단디(AI)는 사진 속 내용을 보지 못합니다. 가족이 적은 메시지를 바탕으로 이야기하고, 사진에 대해서는 어르신께 여쭤봅니다
- 감정·건강 상태 분석은 하지 않습니다(정확성·개인정보 문제). 가족 화면의 ‘교류’는 소식을 보고 이야기했는지만 셉니다
- 가족 연결은 본인인증 없는 초대 숫자 방식(MVP)입니다. 서버에는 가족 열쇠의 해시만 저장하고, 코드 무차별 대입은 10분에 10번으로 막지만, 실서비스에는 휴대폰 인증 등이 필요합니다. 사진 주소는 추측할 수 없는 무작위 이름으로 보호합니다

**향후 개발이 필요한 것**
1. 로그인·본인/보호자 인증, 세션 보안, DB 암호화, 접근 기록
2. 서버형 실시간 음성(스트리밍 STT·자연스러운 TTS), 말소리 끼어들기, 전용 음성 기기·돌봄인형 연동(같은 API·계정 사용)
3. 앱 푸시 알림(어르신이 원할 때만), 가족에게 어르신 대답 전달(어르신 동의 시)
4. 의미 기반 기억 검색(임베딩), 기억 요약·생애 연표
5. 위험 신호 감지와 보호자·기관 알림 — 이번 MVP 제외
6. 개인정보 영향평가, 법률 검토, 접근성 인증(KWCAG), 실제 어르신·가족 사용성 테스트

### 기기와 무관한 구조 (향후 하드웨어 확장)
대화 엔진·기억·가족 연계는 모두 서버 API(`/api/conversations`, `.../messages/stream`, `/api/memories`, `/api/family/*`)에 있고, 브라우저는 마이크·스피커와 화면만 담당합니다. 전용 음성 기기나 돌봄인형을 붙일 때도 같은 API에 같은 어르신 계정으로 접속하면 기억·가족 소식·대화 방식이 그대로 이어집니다(기기는 음성 입출력만 구현).
